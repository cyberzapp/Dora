# Personalized avatar training audit

Reviewed 11 November 2026. This is a source and memory audit supporting the research direction. The user requested research before further implementation. No trained model, avatar generation or optimization step was executed for this audit.

**Decision. None of the three audited training paths currently satisfies the full product requirements.** SyncTalk_2D is the smallest engineering candidate but leaves natural new-speech head and eye behavior unresolved. MuseTalk's full training is a poor fit for 16 GB. MimicTalk has a more relevant personalized renderer, with substantial Mac dependencies and an independently driven pose path. A personalized renderer and a personalized motion generator must be assessed separately.

Pinned source snapshots, SHA-256 hashes and Git blob verification are retained in [the audit manifest](../.local/personalized-source-audit-2026-11-11/manifest.json). The inspected commits are SyncTalk_2D `9e82dccad9a1e5d4aa345df774d74ddff8cc56c4`, MuseTalk `0a89dec45a0192b824e3cf4daf96c239440c5ed8` and MimicTalk `a79f90ed2a91a8ff93f7dd08977b709aeff37d12`. Conclusions below apply to those snapshots.

| Requirement | SyncTalk_2D | MuseTalk adaptation | MimicTalk |
| --- | --- | --- | --- |
| Actual personal training procedure | Yes | General model training can be adapted to personal data | Yes, renderer LoRA and learned triplane |
| New voice-over controls lips | Inference path exists | Inference path exists | Audio-to-expression inference path exists |
| Personal training learns new-speech head and gaze timing | No such component identified | No such component identified | Audited personal trainer adapts appearance rendering; pose/style use additional paths |
| Arbitrary new real outfit photograph | No independent photo-outfit workflow in audited inference | Appearance conditioning exists, quality and motion still need validation | Personal appearance adaptation does not establish reusable arbitrary outfits |
| Ready for M5 training | Explicit CUDA calls need changes | Full training exceeds a practical 16 GB budget | Renderer, fitting and CUDA paths need substantial investigation |
| Ready for application distribution | License and dependency terms unresolved | Transitive models and adapted runtime need review | Transitive components have separate terms |

The table identifies implemented behavior and missing evidence. It does not rank visual quality from demonstrations or infer that a smaller model is more realistic.

SyncTalk_2D uses a 2D convolutional network with image and audio features. Architecture-only metadata accounting found 12,186,935 parameters. FP32 weights, gradients and two Adam moments total approximately 0.182 GiB. That excludes activations, VGG, the synchronization expert and the audio encoder. It establishes a small persistent network state, while training memory and visual quality remain untested. [Architecture](https://github.com/ZiqiaoPeng/SyncTalk_2D/blob/9e82dccad9a1e5d4aa345df774d74ddff8cc56c4/unet_328.py), [accounting evidence](../.local/personalized-source-audit-2026-11-11/synctalk2d-training-memory.json)

Its training samples pair a target frame with a random reference frame. It resizes a facial region to 328 square and uses a central 320-square region. The network predicts RGB from these image inputs and audio features. The audited architecture has no persistent temporal state or audio-driven head-pose output. This limits what personal training alone can solve for the user's motion complaints. [Dataset](https://github.com/ZiqiaoPeng/SyncTalk_2D/blob/9e82dccad9a1e5d4aa345df774d74ddff8cc56c4/datasetsss_328.py)

Inference reads the recorded body frames and landmarks, reverses the frame index at sequence boundaries and replaces the generated central facial region. It therefore retains a recorded performance outside that region. New speech does not determine when the underlying head turns or eyes blink. Its photo-outfit input is also absent from this inference path. [Inference](https://github.com/ZiqiaoPeng/SyncTalk_2D/blob/9e82dccad9a1e5d4aa345df774d74ddff8cc56c4/inference_328.py)

The trainer, landmark extractor and audio preprocessing have hard-coded CUDA device use. Their use of ordinary neural operators suggests a possible port, which is an inference from source inspection. A successful full forward/backward, exact audio-window alignment, safe checkpoint resume and independent validation would be required. The complete recursive tree returned no license-named files. The audio encoder and SCRFD/PFLD checkpoints need explicit provenance and terms. [Trainer](https://github.com/ZiqiaoPeng/SyncTalk_2D/blob/9e82dccad9a1e5d4aa345df774d74ddff8cc56c4/train_328.py), [landmarks](https://github.com/ZiqiaoPeng/SyncTalk_2D/blob/9e82dccad9a1e5d4aa345df774d74ddff8cc56c4/data_utils/get_landmark.py), [audio preprocessing](https://github.com/ZiqiaoPeng/SyncTalk_2D/blob/9e82dccad9a1e5d4aa345df774d74ddff8cc56c4/data_utils/ave/test_w2l_audio.py)

MuseTalk's audited trainer makes the whole UNet trainable, initializes FP32 model weights and uses AdamW by default. The existing local v1.5 configuration contains 849,947,844 parameters. Metadata-only construction gives 13,599,165,504 bytes, or 12.665 GiB, for FP32 UNet parameters, gradients and two optimizer moments. This omits activations, the VAE, Whisper, synchronization and perceptual networks, discriminators, optimizer scratch, the app and macOS. Batch reduction or gradient accumulation does not remove those persistent full-training states. The default recipe is unsuitable for a production training feature on the 16 GB Mac. [Training initialization](https://github.com/TMElyralab/MuseTalk/blob/0a89dec45a0192b824e3cf4daf96c239440c5ed8/musetalk/utils/training_utils.py), [accounting evidence](../.local/personalized-source-audit-2026-11-11/musetalk-training-memory.json)

A limited adapter could reduce optimizer state, but requires a new, tested adaptation procedure. The frozen decoder still participates in the gradient path from image losses to predicted latents. Preprocessing uses Decord and OpenMMLab, and Whisper initialization explicitly selects CUDA. These are additional porting tasks. The trainer reshapes multiple sampled frames into a frame batch before the 2D UNet call. Temporal training losses do not establish a learned head/gaze generator. [Training loop](https://github.com/TMElyralab/MuseTalk/blob/0a89dec45a0192b824e3cf4daf96c239440c5ed8/train.py), [preprocessing](https://github.com/TMElyralab/MuseTalk/blob/0a89dec45a0192b824e3cf4daf96c239440c5ed8/scripts/preprocess.py)

MimicTalk's personal trainer marks renderer LoRA parameters as trainable and optimizes a learned triplane. It uses captured expression/pose coefficients and image losses, including a lip-region perceptual term. That supports appearance personalization, but does not demonstrate training Suman's own audio-to-head-gesture behavior. Its separate inference model loads an audio-to-expression checkpoint and a personalized renderer. [Personal trainer](https://github.com/yerfor/MimicTalk/blob/a79f90ed2a91a8ff93f7dd08977b709aeff37d12/inference/train_mimictalk_on_a_video.py)

Its inference pose can be static or taken from a provided video. The provided-pose path uses mirrored indexing when the reference is shorter than the requested motion sequence. This also needs an explicit long-form motion policy. The default CUDA allocations are spread across fitting, conditioning, training and inference. The SECC renderer calls a CUDA mesh renderer. Some resampling operators include a standard PyTorch fallback, so the presence of CUDA kernels alone does not prove every operation impossible on Mac. Full rasterizer and gradient compatibility remains open. [Inference](https://github.com/yerfor/MimicTalk/blob/a79f90ed2a91a8ff93f7dd08977b709aeff37d12/inference/mimictalk_infer.py), [SECC renderer](https://github.com/yerfor/MimicTalk/blob/a79f90ed2a91a8ff93f7dd08977b709aeff37d12/deep_3drecon/secc_renderer.py)

The root MimicTalk license is MIT, but the included EG3D resampling file has an NVIDIA proprietary license header. Component and pretrained-asset terms need resolution before packaging. A root license is insufficient evidence of permission for every bundled dependency. [Root license](https://github.com/yerfor/MimicTalk/blob/a79f90ed2a91a8ff93f7dd08977b709aeff37d12/LICENSE), [included operator](https://github.com/yerfor/MimicTalk/blob/a79f90ed2a91a8ff93f7dd08977b709aeff37d12/modules/eg3ds/torch_utils/ops/upfirdn2d.py)

The research recommendation is therefore more specific than “train a personalized model.” The selected architecture needs evidence for three linked capabilities. It must preserve Suman's appearance across articulation, produce coherent lip and facial motion for unseen speech, and produce or select appropriate head and eye behavior with temporal continuity. Separate outfit photos remain an independent acceptance requirement. Compact person-specific models are useful comparison candidates, but none passes all four requirements from source inspection.

The next research deliverable should compare the strongest reference-conditioned avatar architectures against a personalized renderer with a separate speech-conditioned motion model. Evaluate capture requirements, available training weights, license coverage and total Mac memory before choosing a port. Use the existing files to define the benchmark. Request the proposed longer capture only after its role in the selected method is clear. The previous rendering jobs remain stopped.

## Follow-up: personalized Gaussian avatars and Metal

Reviewed 11 November 2026, research only. This extends the three-model audit without adopting a new backend. A persistent 3D appearance representation is relevant to identity and temporal stability, but the representation alone does not generate natural speech gestures, eye timing or accurate unseen articulation.

| Candidate | Verified availability | Consequence for Avatar Studio |
| --- | --- | --- |
| GaussianSpeech | Official repository still contains assets and a README announcing future code/data release | Architecture reference; no usable trainer verified. Its published capture uses 16 cameras, unlike Suman's existing monocular footage. |
| Splat-Portrait | Linked official repository is empty at review | Paper claims are not an available implementation or checkpoint. |
| GaussianTalker | Public person-specific training/rendering code and custom rasterizer dependencies | Concrete appearance research candidate, with portability, motion-control and license gaps below. |
| GGTalker | Paper describes pretrained expression/appearance priors and personal adaptation | Relevant design reference. This review did not verify a usable code/checkpoint release or local compatibility. |

Availability sources: [GaussianSpeech repository](https://github.com/shivangi-aneja/GaussianSpeech), [GaussianSpeech capture](https://shivangi-aneja.github.io/projects/gaussianspeech/index.html), [Splat-Portrait repository](https://github.com/stonewalking/Splat-portrait), [GGTalker paper](https://arxiv.org/html/2506.21513v1). These are release observations, not visual comparisons. GaussianSpeech's claimed mouth-interior and wrinkle modeling remains interesting, but its demonstrations do not prove recoverability from a short single-camera capture.

**GaussianTalker source findings.** The audited renderer consumes separate audio, eye and camera features. Camera transforms and eye values arrive with the viewpoint record; this path does not itself establish audio-generated head/eye behavior. Its renderer uses a custom rasterizer with image backgrounds and explicit CUDA allocations. Arbitrary photo-outfit composition and newly timed personal gestures are not established. The root license grants non-commercial research/evaluation use, so this snapshot is not a cleared default for the production creator app. [Renderer](https://github.com/cvlab-kaist/GaussianTalker/blob/250fb9347dfbd370463c575273cc293547aeeaef/gaussian_renderer/__init__.py), [license](https://github.com/cvlab-kaist/GaussianTalker/blob/250fb9347dfbd370463c575273cc293547aeeaef/LICENSE.md)

**Metal changes feasibility, not demonstrated quality.** MetalSplat provides a PyTorch autograd rasterization wrapper, explicit Metal backward dispatch and reference-comparison tests. The audited version declares MIT, alpha status, Python 3.12+ and PyTorch 2.14+. These are source-level facts; its tests have not been executed here. It is a renderer component, not an audio avatar model or an interchangeable replacement for GaussianTalker's custom background/depth rasterizer. [Metadata](https://github.com/tchauffi/metalsplat/blob/84e8c3a433f71c107e9387d3f72a765436c11f6e/pyproject.toml), [autograd wrapper](https://github.com/tchauffi/metalsplat/blob/84e8c3a433f71c107e9387d3f72a765436c11f6e/src/metalsplat/ops/rasterize.py), [gradient tests](https://github.com/tchauffi/metalsplat/blob/84e8c3a433f71c107e9387d3f72a765436c11f6e/tests/test_rasterize.py)

The rasterizer supplies gradients for projected positions, conics, opacity and color. Its depth-order input is detached, and background does not receive a gradient from this wrapper. Whether the intended avatar losses require additional gradients must be checked. Replacing only a CUDA dependency cannot clear the parent avatar code's license or provide missing tracking and motion components.

The practical decision is to retain personalized 3D appearance as a distinct research branch rather than reject it because of NVIDIA-only original code. Before a port, require a complete licensed model/training release, tracking and face-model terms, renderer forward/backward equivalence for that model's actual losses, total memory measurements and a defined head/eye generator. No new capture request is justified until the chosen method's data requirements are established. Keep the Black T photo-outfit requirement in the acceptance set; a fitted head trained from video does not automatically satisfy it.

Pinned source evidence is in `.local/gaussian-avatar-research-2026-11-11/manifest.json`: GaussianTalker `250fb9347dfbd370463c575273cc293547aeeaef` and MetalSplat `84e8c3a433f71c107e9387d3f72a765436c11f6e`. Twelve source files were checked against Git tree blob hashes and SHA-256. No model weights, personal media, inference, training or dependency installation were involved.
