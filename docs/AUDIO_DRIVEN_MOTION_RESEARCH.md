## Why Ditto leads the next comparison

Ditto generates explicit, identity-independent facial motion from audio, then renders the reference appearance. Its paper discusses control over motion and expression. This is relevant to synchronized head, lip and facial movement. It does not prove that the supplied Black T photograph will retain its teeth, skin and identity in every frame. [Paper](https://arxiv.org/html/2411.19509v2)

The published inference source uses a 265-dimensional motion representation and 80-frame windows. It carries a conditioning motion frame between windows and blends overlap. Its pose smoothing applies to the first 202 coefficients. A PyTorch model path is available alongside TensorRT and ONNX. The source therefore offers a plausible path for a Mac investigation without requiring the TensorRT execution path. Plausibility from standard operators still needs a complete device test. [Motion sequencing](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/core/atomic_components/audio2motion.py), [model loading](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/core/utils/load_model.py)

Public checkpoint metadata lists approximately 2.315 GB for the PyTorch model and auxiliary folder, including about 191 MB for the motion checkpoint and 1.461 GB for the HuBERT ONNX component. Those are serialized file sizes, not measured RAM. They justify investigating this candidate before another large video-transformer port. The inference source defaults to CUDA, and its auxiliary ONNX loader selects CPU when the device is not CUDA. The complete path still needs a device, crop and timing audit. [Official checkpoint inventory](https://huggingface.co/digital-avatar/ditto-talkinghead/tree/e4a2f60328ee7c32af585ac4b3cce299e4c8e254/ditto_pytorch)

The training branch provides motion-model training from extracted face motion, audio features, eye information and emotion labels. Its own guide says the small example demonstrates workflow and needs more data and training for reasonable performance. The released PyTorch configuration explicitly sets 1,103 conditioning features, matching the training example; it overrides the inference class default of 1,059. The earlier apparent schema mismatch is therefore resolved at configuration level. Actual checkpoint tensor compatibility has not been tested. A quick fine-tune using the README defaults would not establish a working personalized avatar. [Training guide](https://github.com/antgroup/ditto-talkinghead/blob/7aa0c1b9664de0e3f2c835cbb336392ba58e284b/README.md), [training options](https://github.com/antgroup/ditto-talkinghead/blob/7aa0c1b9664de0e3f2c835cbb336392ba58e284b/MotionDiT/src/options/option.py), [inference architecture](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/core/models/modules/LMDM.py)

The repository declares Apache-2.0. Its checkpoint card has no machine-readable license field in the inspected metadata. The card's prose and each auxiliary asset's terms must be checked before distribution. This is unresolved asset coverage, rather than a conclusion that model use is prohibited. [Code license](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/LICENSE), [model card](https://huggingface.co/digital-avatar/ditto-talkinghead)

## Published controls and the naturalness risk

The pinned 31,002-byte PyTorch configuration was inspected as pickle opcodes without executing its contents. Its SHA-256 is `8e4c9ecb8dbb5aa4d22cb3f9b2c6ceabc62499b04af5fe074826d5b1044c4146`, matching the model inventory. It enables emotion, eye-open, eye-ball and source-shape conditioning. The 1,103 inputs comprise 1,024 speech features, eight emotion values, two eye-open values, six eye-ball values and 63 source-shape values. The configuration includes a supplied emotion array and a nonempty `ch_info` dictionary; these are not Suman-specific learned behavior. [Published configuration](https://huggingface.co/digital-avatar/ditto-talkinghead/blob/e4a2f60328ee7c32af585ac4b3cce299e4c8e254/ditto_cfg/v0.4_hubert_cfg_pytorch.pkl)

The condition handler uses supplied reference information when `ch_info` is present; otherwise it uses the imported source. Multi-frame eye controls traverse that reference forward and backward, while emotion sequences repeat. A single photograph supplies constant eye conditioning unless another track is provided. This does not imply identical rendered eyes: motion synthesis and later controls also affect their appearance. It does mean that “audio-driven” must not be described as learning the person's complete eye and expression behavior from speech. [Condition handler](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/core/atomic_components/condition_handler.py)

The renderer can substitute an eye-expression track, schedule its blinks and apply a pose-based gaze correction. For a photograph, its default driven keys include expression, head angles and translation; for video, the default is expression only. These paths must be compared separately. Reusing camera motion can preserve real movement but cannot establish that those gestures match a new voice-over. Generic generated pose cannot establish Suman's personal speaking style. [Motion controls](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/core/atomic_components/motion_stitch.py)

For any future benchmark, record every effective control after configuration merging. Do not silently inherit the packaged emotion/eye template. Compare source-derived and explicitly documented reference controls while holding speech, seed and appearance fixed. Inspect gaze, blink timing, neck motion and chunk boundaries together. Additional smoothing is an experiment, not a remedy established by this audit.

The upstream export re-encodes the supplied audio as AAC. Avatar Studio must use its original-audio export path and independently verify alignment. This export behavior is separate from the 16 kHz audio analysis used by the model. [Export implementation](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/inference.py)

## Mac execution and appearance audit

Source inspection supports a mixed CPU/MPS feasibility investigation, not a working port. The auxiliary ONNX loader explicitly selects CPU outside CUDA. Neural appearance, motion, stitching, warping and decoding have PyTorch paths. The sampler also stores its own device string, so moving weights alone is insufficient. The renderer performs volumetric `grid_sample`, 3D convolution and large intermediate feature operations. PyTorch has added MPS volumetric sampling support upstream; old reports that this operator was unsupported must not be treated as a present universal blocker. Exact installed-version support, numerical agreement and peak memory remain untested. Do not change interpolation, precision or motion math merely to obtain a successful run. [Loader](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/core/utils/load_model.py), [volumetric motion](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/core/models/modules/dense_motion.py), [PyTorch implementation history](https://github.com/pytorch/pytorch/pull/160541)

The source is cropped at 512 pixels, then resized to 256 for appearance and motion extraction. The default decoder reconstructs a 512-pixel image. Exporting the composited scene at 1080p does not establish 1080p facial detail or preservation of the original skin, hair and teeth. Inspect those features in motion, especially at lip closures and head turns. [Source preparation](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/core/atomic_components/source2info.py), [decoder](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/core/models/modules/spade_generator.py)

Default putback uses a generic crop mask, an affine warp and a Cython blend extension. It is not subject segmentation, and can blend reconstructed pixels over clothing or background within the crop. Pixels outside the mask can retain the original scene, but complete outfit preservation is not established by this implementation. The repository contains a NumPy alternative; equivalence and boundary behavior would need validation before substitution. A precise protected-region composition may be necessary, but cannot correct internal face deformation. [Compositor](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/core/atomic_components/putback.py)

The offline pipeline has six bounded queues, each allowing 100 items. One queue of 100 uncompressed 1920×1080 RGB uint8 frames alone represents about 593 MiB; this is an illustrative capacity calculation, not measured peak memory. Earlier stages can retain feature tensors. Source-video preparation also retains the original frames and per-frame features together, unlike single-photo preparation. A long reference can therefore consume substantial memory despite small serialized model files. Queue bounds and reference caching must be selected from measured total memory, rather than assuming 16 GB is sufficient. [Worker queues](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/stream_pipeline_offline.py), [source registration](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/core/atomic_components/avatar_registrar.py)

This audit leaves Ditto as a candidate for coordinated motion, with a shared LivePortrait-style reconstruction risk. JoyVASA shares a related renderer, so agreement between the two would not independently validate the renderer's identity/detail quality. If both fail the face-detail gate, changing their motion parameters alone is insufficient; revisit a personalized appearance renderer and its training feasibility before further app integration.

## JoyVASA as the comparison

JoyVASA generates pose and facial-expression motion from audio, with prior motion/audio features carried into subsequent windows, and renders through LivePortrait. Its model card describes identity-independent motion trained on Chinese and English footage. Hindi and Hinglish performance remain a separate evaluation. The public motion checkpoint is approximately 414 MB, excluding its audio encoder and renderer dependencies. The repository and motion model declare MIT terms. [Model card](https://huggingface.co/jdh-algo/JoyVASA), [repository](https://github.com/jdh-algo/JoyVASA)

Its wrapper explicitly selects MPS when available. However, source tracing found that the helper constructs DitTalkingHead without passing the selected device. That class defaults to CUDA and moves itself there during construction, before the helper subsequently calls `.to(device)`. The visible MPS branch is therefore insufficient evidence of a working Mac path. This is a specific portability issue to resolve before execution. [Wrapper](https://github.com/jdh-algo/JoyVASA/blob/916a90f8de490e8648fee460c1200bd5d9a795af/src/live_portrait_wmg_wrapper.py), [helper](https://github.com/jdh-algo/JoyVASA/blob/916a90f8de490e8648fee460c1200bd5d9a795af/src/utils/helper.py), [motion model](https://github.com/jdh-algo/JoyVASA/blob/916a90f8de490e8648fee460c1200bd5d9a795af/src/modules/dit_talking_head.py)

The same wrapper pads the analyzed audio by 1,280 samples at the start and 640 at the end at 16 kHz. The visible generation path counts that padded timeline, while the export attaches the original audio. The complete handling of that analysis padding needs a timing audit, including leading and trailing pauses. Do not infer alignment from a valid export. It also accumulates generated frames in memory before writing, which needs attention for full-length videos. [Audio preparation](https://github.com/jdh-algo/JoyVASA/blob/916a90f8de490e8648fee460c1200bd5d9a795af/src/live_portrait_wmg_wrapper.py), [export path](https://github.com/jdh-algo/JoyVASA/blob/916a90f8de490e8648fee460c1200bd5d9a795af/src/live_portrait_wmg_pipeline.py)

These findings support a comparison against Ditto. They do not establish that generated motion will resemble Suman's mannerisms. LivePortrait's renderer and all pretrained landmark/face assets still need individual license and compatibility checks.

## Measured primitive feasibility and a device propagation defect

11 November 2026. A limited local numerical experiment now supplements the source review. This is not model inference: no weights, photos, audio or generated frames were loaded. The earlier statements that no candidate has been run remain true.

`.venv/bin/python` reports PyTorch 2.15.0 on arm64 macOS 27.2. MPS is unavailable inside the restricted process sandbox and available outside it. The experiment therefore ran through the authorized unsandboxed tool path, with `PYTORCH_ENABLE_MPS_FALLBACK=0` set before importing PyTorch. Do not interpret the sandbox result as hardware incompatibility.

The reusable `scripts/probe_avatar_mps_ops.py` compares CPU and MPS FP32 forward volumetric bilinear sampling, with zero padding and `align_corners=False`. Two feature shapes from the audited renderer were exercised: `[22,4,16,64,64]` for sparse deformation and `[1,32,16,64,64]` for the final feature warp. Both passed finite-value and numerical checks; maximum absolute error was `2.384185791015625e-7` for each. Recorded first-dispatch times were about 0.111 s and 0.0024 s respectively. These timings are one-shot primitive observations, not avatar throughput or sustained benchmarks.

This removes lack of FP32 volumetric sampling as a blocker for this installed runtime and these shapes. It does not cover the complete renderer, sampler, memory budget, backward pass, half precision or other inputs. Report: `.local/audio-motion-source-audit-2026-11-11/mps-grid-sample-probe.json`.

A separate source trace identifies a concrete Ditto PyTorch defect for CPU/MPS use: `create_model` accepts `device` as its own parameter, constructs the neural class with only `module(**kwargs)`, then calls `.to(device)`. The neural LMDM constructor therefore retains its default `self.device='cuda'`. Its sampler later uses that string to allocate timestep and noise tensors. Moving parameters and registered buffers does not update that ordinary Python string. The wrapper's own device setting cannot fix this inner state automatically. A future port must propagate the actual device into the sampler or derive allocation devices from its tensors. This is a source-level execution prediction; no candidate checkpoint has been loaded to reproduce it. [Loader](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/core/utils/load_model.py), [sampler](https://github.com/antgroup/ditto-talkinghead/blob/c3e47eee2e626500017a0556b470d6d4182f85e8/core/models/modules/LMDM.py)

The next feasibility work should target real device propagation and the complete neural forward path, rather than replace supported volumetric sampling with different interpolation math. That preserves a fair quality comparison. The rejected rendering direction remains stopped.

## Measured untrained motion-architecture feasibility

11 November follow-up. `scripts/probe_ditto_motion_mps.py` now constructs the verified upstream motion architecture with random weights and synthetic inputs, without invoking its checkpoint loader. Four imported source files are SHA-256 checked against the pinned audit manifest before import. The probe uses the published configuration dimensions: 80 frames, 265 motion features and 1,103 conditioning features. It explicitly passes the device to the neural constructor, avoiding the loader propagation defect without modifying the pinned source.

On the installed PyTorch 2.15.0/MPS runtime, the complete FP32 classifier-free guided forward path returned finite values with CPU fallback disabled. Its measured duration was approximately 0.843 s after the forward check. The stochastic sample was not compared across devices because their random streams differ. This is one untrained sampling observation; it does not measure complete speech encoding, portrait rendering, chunk stitching, real model outputs or total application performance.

Architecture construction counted 47,788,297 parameters, or 191,153,188 FP32 parameter bytes. This excludes buffers, activations, optimizer state and every other pipeline component. It is not a total memory measurement or evidence that training fits.

Evidence: `.local/audio-motion-source-audit-2026-11-11/mps-motion-architecture-50step-probe.json`. The initial two-step report is retained separately. This establishes a credible local execution path for the untrained motion graph. Checkpoint tensor compatibility, real motion quality, the complete renderer and personal identity preservation remain open. No avatar media was generated, and the old rejected pipelines were not restarted.

## Real reference-conditioned articulation comparison

The user reviewed the previous-versus-Ditto comparison and selected “Ditto is closer, but needs work.” This is a baseline preference, not overall quality approval. A subsequent isolated run retained Ditto's pose path and replaced only the six lip-expression triplets with TalkLikeYou predictions. The TalkLikeYou code and three model files were pinned and hash-verified, with source commit `d1088c49071148853c76d8a8f0c1fb97d895758b` and model revision `652b744bbf86510c370ff6f302d046bdd63632e1`. The trained audio encoder, habit encoder, motion generator and temporal smoother executed on MPS with torch CPU fallback disabled. The prepared trajectory is 121×6×3. ## Lip motion window diagnosis

A second SyncNet comparison with a ±4-frame search returned a one-frame offset for the personal articulation clip in all five intervals. In the final interval, confidence dropped to 0.53 and the estimate depended on the search range and interval boundaries. The earlier ten-frame estimate therefore does not establish a real audio delay.

The saved lip coefficients show a different issue. TalkLikeYou uses 100-frame windows with five frames of overlap. It discards the overlapping predictions from the next window and carries the previous window's last prediction into the next window's earlier start. In the 4.84-second test, the jump at frame 100 during the pause was about nine times the preceding step. A separate 300-frame trajectory from the same voice-over showed jumps at 4.0 and 11.6 seconds of about 9.6 and 5.8 times their respective preceding six-step medians. The 7.8-second join was comparable to its nearby motion. These are coefficient measurements and do not establish how noticeable the jumps are in playback.

The longer trajectory and provenance are in `.local/talklikeyou-experiment/prepared-12s/`. The next comparison should align the conditioning frame to each window's start and blend the overlapping predictions, then check the actual rendered joins with the same audio. A global audio shift would leave the coefficient discontinuities in place.
